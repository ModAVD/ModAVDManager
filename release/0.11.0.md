# ModAVDManager v0.11.0

- `ModAVD.exe`：`9ce19a99039809b241fa10f9d8ffb0ee3d13902079658d61b767f0ab0c22accb`
- `tools/modavd.exe`：`d7849ee34c48f58e173a745fc374f4e233e76d08912df8ef93504f1810f36893`

随 ModAVD 0.40.3 进包。下面是相对 v0.10.0 的改动。这一版主要是：新建的实例语言和时区跟着这台电脑；在管理器里更新时，下载期间实例照常能用，关实例之前会列出名字再确认一次；换包期间再打开管理器会提示「正在更新」。

## 新增

- 新建实例的语言和时区跟随这台电脑（只有 Windows）。（ModAVDManager#161，ModAVD/ModAVD#166、ModAVD/ModAVD#141）
  - 语言：新建时按 Windows 的界面语言设置一次，之后在安卓里改成别的会保留。
  - 时区：每次冷启动时按 Windows 的时区传给模拟器。Windows 的时区名是本地化的（比如中文）时，以前模拟器认不出、实例一律用 GMT，现在按固定的对照表换成 IANA 时区名。
  - 已有的实例不变。要改就在实例设置里选，或者用 `modavd set <i> --language host|preserve|<语言> --timezone host|preserve|<IANA 时区>`，下次冷启动生效；新建时也能给这两个选项。
  - `modavd regional <i>` 分别显示设置、这台电脑的值和安卓里现在的值。
  - 语言没设成时，这次新建算没做完，用 `create --resume N` 接着做。

## 变更

- 管理器「设置」里的「更新」：
  - 下载和核对新版期间，可以照常开机、关机、新建和操作实例；下载好以后才不再接收实例操作。这时还有任务或设置修改没做完，就一台实例都不关，下载好的新版留着，做完再点一次。（ModAVDManager#160，ModAVD/ModAVD#170）
  - 有实例在运行时，点「更新」后多一个确认框，列出要关的实例；确认后走正常关机，和点「关机」一样。下载期间又开了别的实例，更新会停下、一台都不关，再点一次「更新」重新确认，不用重新下载。（ModAVDManager#159、ModAVDManager#162）
  - 确认框里不再写「用 AUTO-MAS 的请先更新 AUTO-MAS」。设置页的「要求 AUTO-MAS」一行还在。（ModAVDManager#159）
  - 换包期间再打开管理器，会提示「正在更新，换好后会自动打开管理器」然后退出，不会和换包抢文件。提示由 Windows 自己显示，15 秒后自动关。（ModAVDManager#160、ModAVDManager#162）
  - 已经下好的较新版本，换包前只重新核对一遍，不再联网查一次。（ModAVDManager#160）

## 修复

- 整包更新：
  - 管理器已经取消这次更新并退出、命令行才启动时，不会再把新版换上。（ModAVDManager#162）
  - 命令行启动慢（比如被杀毒软件扫描）时，管理器等它接手的时间从 5 秒放宽到 30 秒，不再白关一次实例；命令行抢启动锁时会重试几秒。（ModAVDManager#162）
  - 进程异常退出留下的交接记录不再挡住下次打开管理器；没人读的取消标记，超过 10 分钟的在下次正常启动时清掉。（ModAVDManager#160、ModAVDManager#162）
  - 管理器开着时用命令行换包，报错直接说「根目录的 ModAVD.exe 正被占用」，并给出下一步。（ModAVDManager#162）
  - 正在发送的一次点击或按键不再让更新失败。（ModAVDManager#162）

## 说明

- 从 v0.10.0 在管理器里点「更新」升到这一版时，下载和关实例由旧管理器做、换包由旧命令行做，所以上面「更新」的改动要到下一次更新才看得到。
- 更新时关实例一律是正常关机，不强制结束。

## 给调用方（AUTO-MAS）

- `protocol` 还是 2：没有删命令、参数和 `--json` 字段，没有新的错误码和退出码。调用方不用改。
- `create`、`set` 多两个可选参数 `--language`、`--timezone`；多一条命令 `regional <i>`。不给这两个参数时，新建的实例语言和时区跟随这台电脑，已有实例不变。（ModAVDManager#161）
- `--json`：`InstanceInfo` 多 `regional`（`{language, time_zone, pending_language?, last_language?, error?}`），根信息多 `regional_supported`，`start` 的结果多 `language_pending`。（ModAVDManager#161）
- 管理器自己的接口：`POST /api/update/apply` 多一个可选的 `confirmed`（确认过要关的实例编号）；多 `GET /api/instances/{i}/regional`；新建和修改实例多 `language`、`time_zone`。（ModAVDManager#161、ModAVDManager#162）
- `update install` 带 `--reopen` 时，先拿根目录的 `.update\manager-handoff.lock`。不带 `--reopen` 的调用不受影响。（ModAVDManager#160）

## 下载与核对

用 Go 1.26.5、`GOTOOLCHAIN=local` 运行仓库里的 `build.ps1`，能编出相同的字节。单独下载的包里还有 Go 的许可原文和文件清单。请用附件 `SHA256SUMS.txt` 核对 zip 和解压出的两个 exe，例如在 PowerShell 里运行 `Get-FileHash .\ModAVDManager-0.11.0-win-x64.zip -Algorithm SHA256`。

单独下载的管理器不会自己更新，新版本要手动替换；ModAVD 包里的那份随 ModAVD 整包一起更新。单独使用时请给 `--root` 或设置 `MODAVD_ROOT`，否则会提示找不到 ModAVD 根目录。不要把单独下载的 zip 解压到 ModAVD 根目录，覆盖整包里的文件。

## English

Shipped in ModAVD 0.40.3. Changes since v0.10.0. This release mostly brings: new instances take their language and time zone from this computer; while the manager downloads an update the instances stay usable, and before shutting them down it names them and asks once more; opening the manager during the swap shows an "updating" notice.

### New

- New instances follow this computer's language and time zone (Windows only). (ModAVDManager#161, ModAVD/ModAVD#166, ModAVD/ModAVD#141)
  - Language: set once at creation from the Windows display language; a later change inside Android is kept.
  - Time zone: passed to the emulator at every cold start from the Windows time zone. Where Windows reports a localized zone name (Chinese, for example) the emulator did not recognize it and the instance ran in GMT; a fixed table now maps it to an IANA name.
  - Existing instances do not change. Change them in the instance settings or with `modavd set <i> --language host|preserve|<language> --timezone host|preserve|<IANA zone>`; it takes effect at the next cold start. `create` takes the same options.
  - `modavd regional <i>` shows the setting, this computer's value and Android's current value.
  - When the language could not be set, that creation is unfinished; continue it with `create --resume N`.

### Changes

- "更新" (update) in the manager's settings:
  - While the new version downloads and is verified, instances can be started, stopped, created and used as usual; only once it is staged are instance operations refused. If a job or a settings change is still unfinished then, no instance is stopped, the staged version stays, and you click again when it is done. (ModAVDManager#160, ModAVD/ModAVD#170)
  - With instances running, a second dialog names the instances to shut down; they are then shut down normally, as "关机" (shut down) does. If another instance was started during the download, the update stops without shutting anything down; click "更新" again to confirm, without downloading again. (ModAVDManager#159, ModAVDManager#162)
  - The dialog no longer says to update AUTO-MAS first. The "要求 AUTO-MAS" (requires AUTO-MAS) row of the settings is still there. (ModAVDManager#159)
  - Opening the manager during the swap shows "正在更新，换好后会自动打开管理器" (updating; the manager opens when done) and exits, so it cannot get in the way of the swap. Windows itself shows the notice, and it closes after 15 seconds. (ModAVDManager#160, ModAVDManager#162)
  - A newer version that is already staged is verified again before the swap without another remote check. (ModAVDManager#160)

### Fixes

- Whole-package updates:
  - When the manager canceled the update and exited before the command line started, the new version is no longer installed. (ModAVDManager#162)
  - With a slow command-line start (an antivirus scan, for example), the manager waits 30 seconds instead of 5 for it to take over, so the instances are not shut down for nothing; the command line retries the launch lock for a few seconds. (ModAVDManager#162)
  - A hand-off record left by a crashed process no longer keeps the manager from opening; cancel marks nobody reads are removed at the next ordinary start once they are 10 minutes old. (ModAVDManager#160, ModAVDManager#162)
  - Installing from the command line with the manager open says that the root's ModAVD.exe is in use and what to do next. (ModAVDManager#162)
  - One tap or key press still on its way no longer fails the update. (ModAVDManager#162)

### Notes

- When "更新" in a v0.10.0 manager updates to this version, the old manager downloads and stops the instances and the old command line swaps, so the update changes above show from the next update on.
- Instances are always shut down normally for an update, never killed.

### For callers (AUTO-MAS)

- `protocol` is still 2: no command, option or `--json` field was removed, and there are no new error codes or exit codes. Callers need no change.
- `create` and `set` take two new optional options, `--language` and `--timezone`; there is a new command `regional <i>`. Without the options a new instance follows this computer's language and time zone, and existing instances do not change. (ModAVDManager#161)
- `--json`: `InstanceInfo` adds `regional` (`{language, time_zone, pending_language?, last_language?, error?}`), the root information adds `regional_supported`, and the result of `start` adds `language_pending`. (ModAVDManager#161)
- The manager's own API: `POST /api/update/apply` takes an optional `confirmed` (the indexes of the instances the user agreed to shut down); `GET /api/instances/{i}/regional` is new; creating and changing an instance take `language` and `time_zone`. (ModAVDManager#161, ModAVDManager#162)
- `update install` with `--reopen` first takes the root's `.update\manager-handoff.lock`. Calls without `--reopen` are not affected. (ModAVDManager#160)

### Download and verification

Running the repository's `build.ps1` with Go 1.26.5 and `GOTOOLCHAIN=local` builds the same bytes. The standalone package also carries Go's license text and the file list. Check the zip and the two extracted exe files with the attached `SHA256SUMS.txt`, for example `Get-FileHash .\ModAVDManager-0.11.0-win-x64.zip -Algorithm SHA256` in PowerShell.

The standalone manager does not update itself; replace it by hand for a new version. The copy in the ModAVD package is updated with the whole ModAVD package. When using it standalone, pass `--root` or set `MODAVD_ROOT`, or it reports that it cannot find the ModAVD root. Do not extract the standalone zip into a ModAVD root over the package's files.
