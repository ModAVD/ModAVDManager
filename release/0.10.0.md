# ModAVDManager v0.10.0

- `ModAVD.exe`：`c2fd1a1437be4267c39e8e990a272b2b6140461877b89db3f8cf0c361d576762`
- `tools/modavd.exe`：`c7fd4fe56022d17b0ef10d5cab80181df643bd3c5fd6f69dce8bcc52c84b599b`

随 ModAVD 0.40.2 进包。下面是相对 v0.9.0 的改动。这一版主要是：开着的实例也登记到默认的 adb server（5037），`adb devices` 和 MAA 这类工具能直接看到；整包更新更稳（断网时能用已经下好的新版、目录链接进入的根目录能自更新、被只读 DLL 占着时换包前就停）；关窗口时卡片不再误显示「开机中」；托盘双击能隐藏和恢复窗口。

## 变更

- 实例开着时，开机守护每 30 秒看一下默认的 adb server（5037）。有人开着它、它又不认识这台实例，就替实例登记过去，那边显示成 `emulator-<控制台端口>`。这样用 `adb devices` 找设备的工具也能看到 ModAVD 的实例，不用再手动 `adb connect`。5037 上没有 server 时什么都不做，不替别人起 server；不想登记就在 `mas-avd.json` 里写 `"shareDefaultAdbServer": false`。modavd 自己的 adb 命令照旧只走根目录的私有 server。（ModAVDManager#155，ModAVD/ModAVD#196）
- 双击托盘图标隐藏或恢复管理器窗口，页面和窗口状态保留；没有窗口时打开一个。单击照旧恢复实例窗口，只是要等系统的双击间隔过去才动，双击不再顺带恢复实例窗口。右键「打开管理器」优先恢复已有窗口。（ModAVDManager#148，ModAVD/ModAVD#188）
- 实例卡片标题下面不再显示运行时长，详情的「状态」一行里照旧有。新建实例去掉「编号」选项，一律用第一个空闲编号；名称的占位文字去掉「比如：」。（ModAVDManager#145）
- 带窗口开机的实例要先装执行桥时，装桥那几次准备用的开机一律无头，装好后正常关机、最后一次才带窗口开，窗口不再弹出、关掉、再弹出好几次。（ModAVDManager#146）
- 开机守护改成每分钟采样一次模拟器内存：提交量比上次记的变化超过 256 MiB 时提前记一行，平稳时照旧每 10 分钟一行；模拟器退出时写一行汇总（最大提交、工作集、采样次数）。（ModAVDManager#153，ModAVD/ModAVD#159）

## 修复

- 关掉模拟器窗口，或者在安卓里关机以后，卡片不再先显示好几秒「开机中」：客体已经够不到、又没有 modavd 在给它开机时，报「关机中」。客体自己重启时，adb 断开的那几秒也报「关机中」。（ModAVDManager#144）
- 整包更新：
  - 根目录里只读的 DLL 被别的程序载入着，或者文件被不许删除的方式打开着时，以前的占用检查查不出来，换到一半才失败。现在换包前就报忙，什么都不动，暂存的新版留着，关掉那个程序再装就行。（ModAVDManager#149，ModAVD/ModAVD#191）
  - 根目录经目录链接（junction、符号链接、8.3 短名）进入时，更新程序认得出自己，能完成自占用检查、替换和中断后的恢复，不再一直报忙。（ModAVDManager#152，ModAVD/ModAVD#195）
  - 断网时，已经下好、核对过、又比装着的版本新的暂存，现在能接着装。管理器点「更新」后的结果提示，每次只在一个窗口里显示一次。（ModAVDManager#154，ModAVD/ModAVD#170）
  - 按区间更新时清单一律从远端取；改动太多时照旧改下整包，原因只写日志。超过 8 MiB 的文件改成边下边写临时文件，不再整块放进内存。读本地文件出错时直接报错，不再误当成包坏了去重下整包。（ModAVDManager#147，ModAVD/ModAVD#182）

## 说明

- 从 v0.9.0 在管理器里点「更新」升到这一版时，换包的还是旧版命令行，它不会把结果交给重新打开的新管理器，所以这一次不会弹「已更新到 …」的提示，实际已经装上了。之后的更新照常提示。

## 给调用方（AUTO-MAS）

- `protocol` 还是 2：没有删命令、参数和 `--json` 字段，没有新的错误码和退出码。调用方不用改。
- `status` / `list --json`：实例自己在关（关了窗口、安卓里关机）时，`status` 照旧是 `starting`，`busy` 是 `stopping`。AUTO-MAS 本来就把 `busy == "stopping"` 当「关闭中」。（ModAVDManager#144）
- `update install` 多一个管理器用的 `--handoff-id`，只和 `--reopen` 一起用；结果改存 `.update\manager-results\<ID>.json`。不用 `--reopen` 的调用不受影响。（ModAVDManager#154）
- 管理器自己的接口多了 `POST /api/update/handoff/take`、`POST /api/update/handoff/receive`，`handoff` 多一个 `id` 字段。（ModAVDManager#154）
- `mas-avd.json` 多一个可选键 `shareDefaultAdbServer`（默认开）。（ModAVDManager#155）

## 下载与核对

用 Go 1.26.5、`GOTOOLCHAIN=local` 运行仓库里的 `build.ps1`，能编出相同的字节。单独下载的包里还有 Go 的许可原文和文件清单。请用附件 `SHA256SUMS.txt` 核对 zip 和解压出的两个 exe，例如在 PowerShell 里运行 `Get-FileHash .\ModAVDManager-0.10.0-win-x64.zip -Algorithm SHA256`。

单独下载的管理器不会自己更新，新版本要手动替换；ModAVD 包里的那份随 ModAVD 整包一起更新。单独使用时请给 `--root` 或设置 `MODAVD_ROOT`，否则会提示找不到 ModAVD 根目录。不要把单独下载的 zip 解压到 ModAVD 根目录，覆盖整包里的文件。

## English

Shipped in ModAVD 0.40.2. Changes since v0.9.0. This release mostly brings: running instances are also registered with the default adb server (5037), so `adb devices` and tools like MAA see them; sturdier whole-package updates (an already downloaded package installs offline, roots entered through a directory link update themselves, a read-only DLL in use stops the update before the swap); the card no longer shows "starting" while a window is being closed; and double-clicking the tray icon hides and restores the window.

### Changes

- While an instance runs, its boot guardian looks at the default adb server (5037) every 30 seconds. When something runs that server and it does not know the instance, the guardian registers the instance there, where it shows as `emulator-<console port>`, so tools that find devices with `adb devices` see ModAVD's instances without a manual `adb connect`. Nothing happens while no server runs on 5037: it never starts one. To turn it off, write `"shareDefaultAdbServer": false` in `mas-avd.json`. modavd's own adb commands still use only the root's private server. (ModAVDManager#155, ModAVD/ModAVD#196)
- Double-clicking the tray icon hides or restores the manager window, keeping the page and the window state; without a window it opens one. A single click still restores the instance windows, but only once the system's double-click time has passed, and a double click no longer restores them too. "打开管理器" (open manager) in the tray menu restores an existing window first. (ModAVDManager#148, ModAVD/ModAVD#188)
- The instance card no longer shows the uptime under its title; the "状态" (status) row of the details still has it. Creating an instance no longer offers an index choice and always takes the first free index; the name placeholder drops "比如：" (e.g.). (ModAVDManager#145)
- When an instance started with a window first needs the arm64 bridge installed, the preparation starts for installing it are all headless; once it is installed the instance shuts down normally and only the last start opens the window, so the window no longer pops up and closes several times. (ModAVDManager#146)
- The boot guardian samples the emulator's memory every minute: a line is written early when the commit changed by more than 256 MiB since the last line, and every 10 minutes as before while it stays steady; when the emulator exits it writes a summary (largest commit, working set, sample counts). (ModAVDManager#153, ModAVD/ModAVD#159)

### Fixes

- After closing the emulator window or shutting down from inside Android, the card no longer shows "开机中" (starting) for several seconds: when the guest cannot be reached and no modavd is starting it, it reports "关机中" (stopping). A guest restarting by itself also shows "stopping" for the seconds adb is gone. (ModAVDManager#144)
- Whole-package updates:
  - A read-only DLL in the root loaded by another program, or a file opened without delete sharing, was missed by the busy check and failed halfway through the swap. Now the update reports busy before the swap, changes nothing and keeps the staged package; close that program and install again. (ModAVDManager#149, ModAVD/ModAVD#191)
  - With the root entered through a directory link (junction, symbolic link, 8.3 short name), the updater recognizes itself and completes the self-occupancy check, the swap and recovery after an interruption instead of reporting busy forever. (ModAVDManager#152, ModAVD/ModAVD#195)
  - Offline, a staged package that was downloaded and verified and is newer than the installed version now installs. After "更新" (update) in the manager, the result is shown once, in one window. (ModAVDManager#154, ModAVD/ModAVD#170)
  - Range updates always take the manifest from the server; with too many changes they still fall back to the whole package, with the reason only in the log. Files over 8 MiB go to a temporary file as they download instead of into memory. Local read errors are reported as such instead of being taken for a broken package and downloading the whole package again. (ModAVDManager#147, ModAVD/ModAVD#182)

### Notes

- When "更新" in a v0.9.0 manager updates to this version, the old command line does the swap and does not hand its result to the reopened manager, so this one time there is no "updated to …" message although the update was installed. Later updates show it as usual.

### For callers (AUTO-MAS)

- `protocol` is still 2: no command, option or `--json` field was removed, and there are no new error codes or exit codes. Callers need no change.
- `status` / `list --json`: while an instance is shutting itself down (window closed, shut down inside Android), `status` is still `starting` and `busy` is `stopping`. AUTO-MAS already treats `busy == "stopping"` as stopping. (ModAVDManager#144)
- `update install` has a new manager-only `--handoff-id`, only with `--reopen`; the result is stored in `.update\manager-results\<ID>.json`. Calls without `--reopen` are not affected. (ModAVDManager#154)
- The manager's own API adds `POST /api/update/handoff/take` and `POST /api/update/handoff/receive`, and `handoff` gets an `id` field. (ModAVDManager#154)
- `mas-avd.json` gets an optional key `shareDefaultAdbServer` (on by default). (ModAVDManager#155)

### Download and verification

Running the repository's `build.ps1` with Go 1.26.5 and `GOTOOLCHAIN=local` builds the same bytes. The standalone package also carries Go's license text and the file list. Check the zip and the two extracted exe files with the attached `SHA256SUMS.txt`, for example `Get-FileHash .\ModAVDManager-0.10.0-win-x64.zip -Algorithm SHA256` in PowerShell.

The standalone manager does not update itself; replace it by hand for a new version. The copy in the ModAVD package is updated with the whole ModAVD package. When using it standalone, pass `--root` or set `MODAVD_ROOT`, or it reports that it cannot find the ModAVD root. Do not extract the standalone zip into a ModAVD root over the package's files.
